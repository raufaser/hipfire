B-trees and LSM-trees are the two dominant structures for high-ingest time-series workloads. B-trees optimize for read amplification and point queries, while LSM-trees optimize for write amplification and sequential ingest. Hash indexes provide constant-time point lookups but cannot serve range scans efficiently. Tries trade memory for prefix compression and lexicographic ordering. The choice between them depends on the ratio of reads to writes, the latency budget for point versus range queries, and the cost model of the underlying storage medium.

Write amplification is the central enemy of sustained ingest throughput. Every byte the application writes can turn into several bytes of device I/O once compaction, garbage collection, and index maintenance are accounted for. Tiered compaction bounds write amplification at the cost of higher read amplification, while leveled compaction minimizes read amplification but multiplies write amplification. The operator must measure both under production-shaped traffic rather than trusting vendor benchmarks run on idle hardware.

Concurrency control for a storage engine under high ingest is a study in tradeoffs. Optimistic schemes keep the fast path latch-free but pay abort costs when writers collide on hot keys. Pessimistic locking serializes cleanly but risks convoy effects when a slow transaction holds a page latch across an I/O stall. Multiversion schemes let readers proceed without blocking writers, at the price of version-chain traversal and garbage collection of obsolete versions.

Cache behavior decides more real-world queries than asymptotic complexity. Prefetching hides latency only when access patterns are predictable, which is why columnar layouts and clustered indexes keep winning for scan-heavy analytics. Fractal trees and cache-oblivious layouts attempt to be optimal at every level of the hierarchy simultaneously. Compaction scheduling is where LSM-tree deployments live or die. A scheduler that falls behind lets the number of sorted runs grow without bound, and read amplification follows it off a cliff. Rate limiting incoming writes to match compaction throughput keeps the system stable but sacrifices ingest peaks. Write amplification is the central enemy of sustained ingest throughput. Every byte the application writes can turn into several bytes of device I/O once compaction, garbage collection, and index maintenance are accounted for. Tiered compaction bounds write amplification at the cost of higher read amplification, while leveled compaction minimizes read amplification but multiplies write amplification. The operator must measure both under production-shaped traffic rather than trusting vendor benchmarks run on idle hardware.

Concurrency control for a storage engine under high ingest is a study in tradeoffs. Optimistic schemes keep the fast path latch-free but pay abort costs when writers collide on hot keys.
